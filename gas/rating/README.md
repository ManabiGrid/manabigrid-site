# レッスン評価の受信処理

`Code.gs` は、本人の Google アカウントで動かす Google Apps Script（GAS）の Web アプリ用コードです。回答を非公開の Google スプレッドシートへ保存します。**現時点ではデプロイも実サービスとの通信確認も行っていません。サイト側の接続先設定は空のままにしてください。**

GAS の ContentService は、応答を一時的な `script.googleusercontent.com` の URL へ転送します。[Google 公式の転送仕様](https://developers.google.com/apps-script/guides/content#redirects)に記載があります。今回のサイトの Content Security Policy（CSP。ブラウザーが接続を許可する相手の制限）は `script.google.com` だけを許可するため、GET の集計 JSON を読み取れません。POST の `no-cors` 送信でも応答を読み取れず、初回の `doPost` 到達とシートへの保存は未確認です。URL を設定するだけで利用可能とは判断できません。実際の有効化には、通信先の条件変更に対する別の承認、または別方式への設計変更が必要です。このコードは接続先ホストを追加しません。

## 保存する内容

シート名は `ratings` です。1行目は次の5列で固定します。受信時刻はサーバー側の `Date` として保存し、表示形式はスプレッドシートの設定に従います。

| 列 | 保存する値 |
| --- | --- |
| `timestamp` | 受信処理が記録した時刻 |
| `unit` | 単元ID。英小文字・数字・ハイフンによる3〜80文字 |
| `lesson` | `L` と数字2桁によるレッスンID |
| `rating` | `got`（わかった）・`hard`（すこしむずかしい）・`lost`（わからなかった）のいずれか |
| `reason` | 空欄、または後述の理由コード |

理由コードは `examples`（例が足りない）・`wording`（ことばが難しい）・`jump`（話が飛ぶ）・`error`（まちがいがありそう）の4種類だけです。`hard` または `lost` の回答にだけ付けられます。自由記述、メールアドレス、IPアドレス、端末識別子、閲覧履歴はコードから取得せず、保存する列も設けません。Google による通常の通信処理と、このコードがシートへ保存する内容は別です。

最初の回答と理由の追送は、別の行になる場合があります。理由付きの行は理由回答として扱い、評価の総票数に重ねて加えないでください。公開する件数は、理由が空の `got` 行だけを単元全体で合計します。レッスン別、`hard` / `lost` 別、理由別の集計値や回答行は外部へ返しません。

## 本人が行う準備と公開

以下は**本人が行う操作**です。AI はスプレッドシート作成、権限付与、Web アプリのデプロイ、設定URLの入力を行っていません。上記の通信方式が解決するまでは準備手順として扱ってください。

1. **本人**: 自分の Google アカウントで新しいスプレッドシートを作成します。共有範囲は自分だけにします。シートのウェブ公開やリンク共有は行いません。
2. **本人**: スプレッドシートの「拡張機能」から Apps Script を開き、`Code.gs` のコードを貼り付けます。既存の無関係なスクリプトを上書きしないでください。
3. **本人**: `RATING_CONFIG.spreadsheetId` の仮値を、新しいスプレッドシートURLの `/d/` と次の `/` の間にあるIDへ置き換えます。シートIDをサイト設定へ書く必要はありません。
4. **本人**: エディターで `prepareRatingSheet` を1回実行し、本人のスプレッドシートへのアクセスを承認します。この関数は `ratings` シートと5列の見出しを準備します。既存行を削除しません。作成後は `ratings` の列や見出しを変更しないでください。
5. **本人**: 「デプロイ」から「新しいデプロイ」を選び、種類を「ウェブアプリ」にします。「次のユーザーとして実行」は自分にします。「アクセスできるユーザー」は「全員」を選びます。公開するのは受信処理です。スプレッドシート自体の共有は変更しません。アカウントの制限で「全員」を選べない場合は、公開設定を迂回せず停止してください。
6. **本人**: デプロイ後の `https://script.google.com/macros/s/…/exec` URLを控えます。`/dev` URLは使いません。OAuth トークンなどの認証情報はサイトへ設定しません。
7. **本人／AI**: 通信方式の条件を解決し、本人が接続先を確認した後にだけ、サイト側の `site.config.json` の `rating_endpoint` へ `/exec` URLを設定します。このキーは回答の受信先です。空の間は評価用のHTML・JavaScript・CSSを生成しません。サイトコードの変更は、このリポジトリのPR検証と公開承認を別途通します。GAS のデプロイ完了をサイトの公開完了とは扱いません。
8. **本人／AI**: 実サービスへの書込みとブラウザーからの集計読取りを、それぞれ明示的に確認してから有効化完了とします。POST の送信開始や画面表示だけを保存成功の証拠にしません。

受信処理を止める場合は、本人が GAS のデプロイを無効化し、サイト設定も空へ戻します。既存の回答はシートに残ります。回答の削除や保存期間の決定は、このコードで自動実行しません。

## POSTの契約

`doPost` は、`URLSearchParams` で作る `application/x-www-form-urlencoded;charset=UTF-8` の本文だけを受け付けます。本文の上限は512文字です。必須キーは `unit`・`lesson`・`rating`、任意キーは `reason` だけです。

```javascript
new URLSearchParams({unit: 'jhs-math-example', lesson: 'L01', rating: 'got'})
new URLSearchParams({unit: 'jhs-math-example', lesson: 'L01', rating: 'hard', reason: 'examples'})
```

これらは説明用の架空の単元IDです。上記コードは送信しません。実際のフォーム本文を重複キーを保持したまま解析し、次の入力を保存前に拒否します。

- キーの重複。`unit` と `%75nit` のようにデコード後に重なるキーも拒否します。
- 未知のキー、自由記述、空の理由、未知の理由、`got` に付けた理由。
- JSON、`text/plain`、ファイル添付、POST URL側のクエリーパラメーター。
- 不正な文字コード、単元IDやレッスンIDの形式違い、本文上限の超過。

保存に成功した場合のJSONは `{"ok":true}` です。失敗時の形式と固定コードは次のとおりです。例外の詳細やシートの情報を応答へ含めません。ContentService で返すJSONなので、HTTPステータスだけを成否の判断に使わないでください。

| JSON | 意味 |
| --- | --- |
| `{"ok":false,"error":"invalid_request"}` | 入力形式や値を拒否しました。保存しません。 |
| `{"ok":false,"error":"rate_limited"}` | 直近60秒の受付上限です。保存しません。 |
| `{"ok":false,"error":"busy"}` | 同時処理用のロックを取得できませんでした。保存しません。 |
| `{"ok":false,"error":"service_unavailable"}` | 未設定、シートの不整合、キャッシュまたは保存処理の失敗です。保存途中に失敗した場合は、保存済みか不明なことがあります。 |

サイト側は `no-cors` で送信するため、このJSON応答を読めません。応答が読めないことや通信失敗を理由に自動再送しないでください。保存結果が不明な再送は二重記録になる場合があります。

## GETの契約

`doGet?unit=jhs-math-example` の形式で、単元IDを1個だけ受け付けます。POSTと同じ単元IDの形式制限を使い、重複キーや追加キーを拒否します。成功時のJSONは次の形だけです。

```json
{"unit":"jhs-math-example","got":null}
```

`got` が0〜10件なら、件数によらず `null` を返します。11件以上なら、その単元の `got` の合計を整数で返します。たとえば11件なら `{"unit":"jhs-math-example","got":11}` です。これは匿名の回答行数であり、11人の別人を確認した値ではありません。入力拒否、連投制限、競合、取得失敗のJSONはPOSTと共通です。フロントエンドは `null` や取得失敗の場合に件数を表示しません。

## 連投制限と匿名回答の限界

CacheService（GAS の一時保存機能）に受付時刻を保存し、LockService（同時実行の競合を防ぐ機能）のスクリプトロック内で検査します。上限に達した場合はシートへ書き込みません。

- GETとPOSTの合計は、同じスクリプト全体で直近60秒に120件までです。
- POSTはさらに、同じ単元IDとレッスンIDの組で直近60秒に20件までです。理由の追送も1件に数えます。
- ロックの取得は最大2秒待ちます。取得できなければ `busy` を返します。
- 形式が正しいリクエストは、後続のシート処理が失敗しても受付上限を消費する場合があります。

これらは負荷を減らすための上限です。CacheService の値は期限前にも失われる場合があるため、厳密な不正投票防止を保証しません。取得できたキャッシュが壊れていた場合やサービスで例外が出た場合は、書き込みを始めず失敗を返します。大量データのGETはシート全行を走査するため、GAS の実行上限を超える場合があります。自動の外部転送や別サービスへの拡張は行いません。

匿名の同一端末・同一レッスンにつき1日1回という制限は、フロントエンドのローカル保存による補助だけです。GAS には個人や端末を特定するIDを送りません。ブラウザーの保存データの消去、別ブラウザー、別端末、直接のHTTP送信で回避できます。送信元を認証する処理や、本人の重複を完全に排除する処理はありません。

## 検証済みの範囲

`tests/test_rating_gas.py` は Node.js の隔離した実行環境に、スプレッドシート・キャッシュ・ロックの代用品を置いて検証します。Google へのリクエストは発行しません。

```bash
python3 -B -m unittest discover -s tests -p 'test_rating_gas.py' -v
```

入力拒否、5列の保存、10件と11件の境界、理由回答の除外、全体とレッスン単位の60秒上限、ロック競合、保存失敗、見出しの不整合を検証します。実際の GAS 実行、Google の権限画面、スプレッドシートへの保存、CSP と転送を含むブラウザー通信は未確認です。
